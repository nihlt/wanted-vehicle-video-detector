# Датасет: кадри з машинами і номерами

> **У репо лише розмітка:** `labels_draft.json` (номери на вирізках машин: його читають `find_plates.py`, `plates_nn.py` і `check_plates_clip.py`) та `clip/gt/` (еталон машин у хвилині 4:50–5:50: `fragments.json` і `labels.json` для `gt_tracks.py`, готовий еталон `tracks_gt.json` для `compare_trackers.py`). Дослідницькі скрипти лежать у `tools/research/`. Кадри, вирізки й аркуші в репо не входять, бо їх відтворюють ці скрипти з відео. Файлу `labels.json` (формат описано нижче) у репо теж немає.


Перша партія кадрів з `bus-driving.webm` з правильними відповідями: де на кадрі номерні знаки і що на них написано.
Навіщо: щоб код, який шукає й читає номери, можна було перевіряти цифрами, а не на око.

## Що всередині

- `images/` — кадри 1920×1080 з оригінального відео (не з перекодованого кліпу, щоб дрібний текст не втрачав різкість).
  Ім'я файлу — час у відео: `t0070.0.jpg` = кадр на 70.0 с.
- `labels.json` — розмітка (формат нижче).
- `preview/` — аркуші для перевірки розмітки очима:
  - `frames_NN.jpg` — кадри з рамками всіх номерів;
  - `plates_NN.jpg` — кожен номер збільшено, поруч розмічений текст.

## Формат `labels.json`

```json
{
  "video": "bus-driving.webm",
  "images": [
    {
      "file": "images/t0070.0.jpg",
      "time": 70.0,
      "width": 1920, "height": 1080,
      "plates": [
        { "id": "p003", "text": "AO1234BC", "bbox": [812, 774, 96, 24] },
        { "id": "p004", "text": null,       "bbox": [1500, 690, 40, 12] }
      ]
    }
  ]
}
```

- `bbox` — `[x, y, w, h]` **у пікселях** кадру, від лівого верхнього кута. (У плеєрі рамки нормалізовані до 0–1; тут пікселі, бо так простіше перевіряти.)
- `text` — латиницею, без пробілів. Кириличні літери, схожі на латинські (А, В, Е, І, К, М, Н, О, Р, С, Т, Х), записуємо латинськими: `АО` → `AO`.
- `id` — ідентифікатор конкретного номера. Якщо та сама машина є на кількох кадрах, `id` однаковий.

## Правила розмітки

1. Рамку отримує кожен номер, який видно як номер.
2. Якщо всі символи читаються впевнено — пишемо `text`. Якщо хоч один символ під сумнівом — `text: null`. Часткових відповідей на кшталт `AO45??HI` немає.
3. Номери з `text: null` при оцінці — «зони ігнорування»: якщо код знайде там номер, це не помилка, але й не заслуга.
4. Рамка обходить саму табличку номера (з синьою смужкою UA, якщо вона є), без кріплень і рамок-тримачів.
5. Один і той самий номер — не більше ніж на 2–3 кадрах, інакше одна машина «важить» у результаті забагато.
6. Розмітка зроблена вручну по збільшених фрагментах кадрів у повній роздільності, без жодного алгоритму детекції — щоб датасет не перевіряв алгоритм сам собою.

## Як відбирались кадри

1. Переглянуто кадри кожні 10 с по всьому відео і знайдено ділянки, де є машини.
2. На цих ділянках витягнуто кадри кожні 2 с (`tools/research/extract_frames.py`) і складено в аркуші (`tools/research/contact_sheet.py`).
3. З аркушів вибрано кадри, де є хоча б один номер, який людина може прочитати.

Перевірочні аркуші генеруються так: `python tools/research/make_preview.py dataset`.
