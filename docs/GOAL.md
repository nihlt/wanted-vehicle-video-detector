# Розпізнавання автомобілів і номерів на відео

## Мета

Програма, яка знаходить на відео автомобілі, читає їхні номерні знаки і показує результат у браузерному плеєрі.
Під відео є стрічка знайдених машин. Між ними можна переключатись, і відео одразу показує потрібну машину.

## Етапи

| Етап | Що робимо | Результат |
|---|---|---|
| 0. Мок (зроблено) | Плеєр на реальному фрагменті `bus-driving.webm`, машини розмічені вручну | `mock/` — видно, як це має виглядати і як ним користуватись (у репо не входить) |
| 1. Обробка файлу (зроблено) | Завантажене відео проходить через детекцію, трекінг, розпізнавання номера (OCR) і визначення атрибутів. На виході JSON у тому ж форматі, що й мок | Той самий плеєр, але з реальними даними |
| 2. Реальні системи | Живі потоки (RTSP / IP-камери), кілька камер, збереження в БД, пошук по номеру | Інтеграція з зовнішніми системами |

## Плеєр (узгоджений UX)

- Відео зверху, під ним **стрічка карток машин** у хронологічному порядку (за кадром, на який веде клік, тож «наступна» завжди рухає відео вперед).
- Картка: мініатюра машини, **номер**, **час появи**, **тип** (легкова / вантажівка / автобус / мото), **колір**, **регіон** (за кодом номера).
- **Клік по картці**: відео переходить на кадр, де номер видно найкраще, і **ставиться на паузу**. Машина обведена рамкою, номер окремою рамкою, у бічній панелі збільшений номер.
- **Попередня / наступна машина**: кнопки і клавіші ← / →.
- Під час відтворення підсвічуються картки машин, які зараз у кадрі. На таймлайні є мітки появи машин.
- Машини з нерозпізнаним номером або з низькою впевненістю позначаються окремо.

## Формат даних (контракт між обробкою і плеєром)

Час задаємо в секундах від початку відео, не номером кадру, бо у вихідного відео змінна частота кадрів.
Координати нормалізовані до 0–1 (`[x, y, w, h]` від лівого верхнього кута).
Повний приклад цього формату був у макеті `mock/data.js`. Дані етапу 1 побудовані так само, але з рамками на кожному кадрі: див. `demo/data.js`.

```js
{
  source: {
    id: "bus-driving",          // ідентифікатор відео
    camera_id: "bus-front",     // для етапу 2: з якої камери
    file: "clip.mp4",
    duration: 120.0,
    width: 1920, height: 1080,
    offset_in_original: 290.0,  // зсув фрагмента у вихідному файлі (лише для моку)
    original_file: "bus-driving.webm"
  },
  vehicles: [
    {
      id: "v001",
      first_seen: 12.4,         // коли з'явилась у кадрі
      last_seen: 18.9,          // коли зникла
      best_time: 15.2,          // кадр, де номер видно найкраще
      bbox: [0.02, 0.62, 0.43, 0.38],      // машина на кадрі best_time
      vehicle_type: "car",      // car | truck | bus | moto | van
      color: "black",
      plate: {
        text: "AO4523HI",       // латиницею, без пробілів; null якщо не прочитано
        confidence: 0.94,       // 0–1; нижче 0.75 плеєр позначає номер як сумнівний
        bbox: [0.04, 0.91, 0.07, 0.04],
        region_code: "AO",      // null для індивідуальних та іноземних номерів
        country: "UA",          // UA | CZ | ... | null, якщо формат невідомий
        background: "white"     // white | yellow
      },
      thumb: "crops/v001_car.jpg",
      plate_crop: "crops/v001_plate.jpg"
    }
  ]
}
```

На етапі 1 до кожної машини додається `track: [{ t, bbox }, ...]`, тобто рамки по кадрах.
Тоді рамка зможе рухатись за машиною і під час відтворення, а не тільки на паузі.

## Мок (етап 0)

> Макет лишився з першого етапу і в репо не входить. Робоче демо — `demo/` (див. README).

Відкрити `mock/index.html` у Chrome (подвійний клік, сервер не потрібен).

- `mock/clip.mp4`: фрагмент 4:50–6:50 з `bus-driving.webm`, перекодований у H.264 з ключовим кадром кожні 30 кадрів, щоб перехід до машини був миттєвим. Відео в репо немає, кліп робиться з вихідного відео (див. README):
  `ffmpeg -ss 290 -i bus-driving.webm -t 120 -an -c:v libx264 -crf 18 -preset fast -g 30 -pix_fmt yuv420p mock/clip.mp4`
- `mock/data.js`: 15 машин, розмічених вручну у форматі вище. Серед них є складні випадки: номер не видно (машина боком), низька впевненість, жовті номери, індивідуальний `LS988`, чеський `2TX 2967`.
- `mock/crops/`: кропи машин і номерів з кадрів кліпу.
- Клавіші: ← / → — попередня / наступна машина, пробіл — відтворення, Esc — зняти вибір, / — пошук.

## Вихідні дані

- `bus-driving.webm`: 23:29, 1920×1080, VP9, близько 60 кадрів/с (змінна частота), міська поїздка, знято з автобуса.
- Номери українські, наприклад `AO 4523 HI` (6:40).

## Відкриті питання

- Модель детекції авто (наприклад, YOLO) і OCR номерів: обрати й порівняти на етапі 1.
- Довідник регіональних кодів номерів: у моку лише кілька кодів, їх треба звірити з офіційним переліком.
- Повторні появи того самого номера: об'єднувати в одну картку чи показувати окремо?
- Припарковані машини: показувати всі чи тільки ті, що рухаються?
- З якими саме системами інтегруватись на етапі 2.
- Номери машин — це персональні дані: де і скільки їх зберігати, хто має доступ.
